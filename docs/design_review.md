# 디자인 자문 결과 요약 (Gemini + ChatGPT, 2026-11-05)

의뢰서: `design_brief.md`. 두 AI의 답을 비교해 앱에 적용할 안을 골랐다. 시안 속 단지명·금액은 모두 가상 데이터다.

## 채택할 방향 (A안: 기존 4탭·단계별 섹션 유지)
1. 목록 상단에 "오늘 놓치면 안 되는 청약" 요약 띠(접수 N건·마감 N건) — P0
2. 카드 위계 정리: 공고명·상태 > 접수 날짜 > 분양가·세대수 > 지역·출처·유형. 유형 태그는 상태 배지보다 약하게 — P0
3. 마감 섹션은 기본 접힘 — P0
4. 상세: 상단 핵심 3칸(접수 기간 / 분양가 범위 / 공급 세대) → 일정 → 주택형별 공급(접기) → 부가 정보(접힘) → 하단 고정 버튼 — P0
5. 일정 타임라인(공용 컴포넌트): 현재 데이터 4개(접수 시작·마감·당첨자 발표·계약 시작)로 시작, 없는 단계는 억지로 만들지 않음 — P1
6. 라이트·다크 토큰 통일 — P1
7. 온보딩 3단계(지역·유형 → 키워드 → 알림), "나중에 설정하기" 제공, 알림 권한은 켤 때만 요청 — P1
8. 추후 검토: B안(오늘 중심 홈: 오늘 / 전체 공고 / 캘린더 / 내 일정), Gemini의 "오늘의 액션" 캐러셀 — P2

## 타이포·간격
- 폰트: Pretendard (폴백 Noto Sans KR). 번들하려면 용량·라이선스(OFL) 확인 필요
- 화면 제목 24/32 w700, 핵심 숫자 22/30 w700, 카드 제목 18/26 w700, 섹션 제목 17/24 w700, 본문 15/23, 부가 13/19, 배지·태그 12/18 w600, 주의 문구 11/17
- 간격 4·8·12·16·20·24·32dp, 카드 패딩 16, 카드 모서리 16, 태그 8, 칩·버튼 12, 최소 터치 48dp
- 그림자는 거의 쓰지 않고 옅은 테두리와 배경 명도 차이로 구분

## 구현 시 주의
- 카드·상단 3칸은 고정 높이 금지. 큰 글자(1.3~2.0배)에서는 3열 → 1~2열로 재배치(Wrap)
- 값이 없으면 추정하지 말고 "미공개"/"원문 확인"으로 표시. 임대·장기전세는 "최고 분양가" 대신 보증금·임대료 항목
- 서버 없는 앱이므로 "마지막 갱신 시각"을 보여주고, 변경·취소는 원문 재확인 안내
- Gemini의 특별공급/1순위/2순위 타임라인은 해당 날짜를 수집(청약홈 API)한 뒤에 가능
